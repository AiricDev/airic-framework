# Application UI, host and ACP

The Application owns its business navigation, dashboard, lists, detail/edit/review pages and access policy. Airic's Work and Module APIs are headless; a module contributes its own Experience without copying the Framework UI. Keep application business storage separate from the Airic runtime directory. Report or other business objects, approvals and exports remain authoritative in module Application Services, never in Agent messages or ACP session state.

Compose `AiricRuntime` in the application entry point. The host creates one Node HTTP server with a fixed route order: business API under `/api/app/**`, the Airic handler under `/api/airic/**` (`createAiricHttpHandler`), production static assets (`createStaticHandler`), then a structured 404. The host establishes a trusted actor from its authentication mechanism; HTTP input cannot override actor, scopes, Work identity or command identity. Give HTTP/SSE, ACP and Runtime the same host-owned `AiricAccessPolicy`/`authorizeWork` decision so delivery and capability execution are rechecked. Work creation records `createdBy` from that actor; do not silently grant browser access to older Works lacking trusted ownership. Module imports and WorkType capability allowlists do not themselves grant user permission.

For a browser Agent panel, optionally mount `@airic/acp` on the same server's WebSocket upgrade path. First create or open an authorized Work; then use `GET /api/airic/works/:id/agent-connection` to obtain the host-fixed `{ url, cwd, sessionId? }`. With an ACP client, call `initialize`, then `session/new` once or `session/load` on reconnect, using that exact absolute `cwd`, no extra directories and no client-supplied MCP servers. Send text through `session/prompt`, use `session/cancel` for the active turn, and show streamed `session/update` text/tool phases as progress only. On disconnect, reload the session from Airic trace and refresh Work and business data over HTTP. Stop reconnecting on 401/403 and show a clear forbidden state. The host configures a trusted public origin for the returned WebSocket URL and strict Origin check; do not trust the request Host header or expose browser filesystem/terminal capability. ACP permission prompts cannot approve a business action.

`AiricWorkbench` remains an optional generic development/audit surface, not the required application shell. If used, pass the `client` prop or provide `AiricProvider` from `@airic/ui` around a `createAiricClient` from `@airic/client`; `apiBase` is deprecated. Register result views by business reference and load the authoritative object through the business API. Module browser contributions may provide business navigation, pages and result views; server contributions provide routes, DomainProviders and explicitly named public services. The Application loads modules in dependency order without per-module edits to `src/main.ts`, `src/client.tsx` or global route tables.

SSE and ACP are projections of canonical Airic trace. Reconnect SSE with the last event ID; on ACP reconnect use `session/load`. Both must filter by the current actor's Work visibility, and a refresh must rebuild visible state through HTTP. A lost transport reply is not proof that a business command failed: query the business state or stable command receipt before retrying.
